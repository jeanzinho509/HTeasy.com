## 2026-07-06 - [Mass Assignment Privilege Escalation in User Registration]
**Vulnerability:** A mass assignment vulnerability in `server/controllers/auth.controller.js` allowed privilege escalation. The `register` function was extracting `role` from `req.body` and assigning it directly to the new user without any authorization checks. This meant any user could register as an 'admin' by simply including `{"role": "admin"}` in their registration payload.
**Learning:** This vulnerability is a recurring issue in this codebase, representing a regression. The root cause is blindly trusting user input in the registration endpoint and allowing it to dictate sensitive model attributes. When objects are built dynamically from request bodies, attributes like roles, permissions, or ownership IDs must be explicitly stripped or hardcoded.
**Prevention:** To prevent this, always decouple sensitive internal states from user input. In this case, `role` must be removed from the `req.body` destructuring entirely, and the role for new registrations must be explicitly hardcoded to a safe default (e.g., `const userRole = 'user';`).
