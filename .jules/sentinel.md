## 2024-05-14 - Privilege Escalation via Mass Assignment in Registration
**Vulnerability:** The `/api/auth/register` endpoint destructured `role` directly from the user-provided request body and used it when inserting the new user into the database (`const { name, email, password, phone, role } = req.body;`). This allowed any user to register as an administrator by simply passing `{"role": "admin"}` in their registration request.
**Learning:** This existed because of a combination of convenience (using destructuring to grab all potential fields) and a lack of explicit allowlisting for what a user is permitted to set during account creation. It's a classic Mass Assignment vulnerability where internal model properties are exposed to external input.
**Prevention:** Never trust client input for sensitive fields like roles, permissions, or account balances. Explicitly extract only the allowed fields from requests. Hardcode default roles for new signups and require an authenticated, authorized admin endpoint (or out-of-band process) to elevate user privileges.
