## 2024-05-15 - Privilege Escalation via Mass Assignment in Registration
**Vulnerability:** The `/api/auth/register` endpoint accepted a `role` field from the client request body and used it directly when inserting the user into the database (`const userRole = role || 'user';`). This allowed any user to create an `admin` or `seller` account by simply sending `{"role": "admin"}` in their registration request.
**Learning:** Destructuring request bodies without input validation (`const { role } = req.body`) and using those directly in database insertions or updates leads to mass assignment vulnerabilities. The comment claimed "unless specified and user is authorized" but there was no actual authorization check.
**Prevention:** Hardcode roles for public registration endpoints (`const userRole = 'user'`). For updates, explicitly pick only the allowed fields rather than using the entire request body. Administrative fields like `role` should only be modifiable via dedicated, protected endpoints.
