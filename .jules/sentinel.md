## 2024-05-23 - Sensitive File Exposure via Root Static Serving
**Vulnerability:** The application was serving the root directory `/` via `express.static(path.join(__dirname, '/'))`. Because backend files (`server.js`, `/server/`, `.env`, `package.json`, etc.) reside in the root alongside frontend files (`index.html`, `style.css`), this allowed unauthorized users to download critical secrets and source code by making standard HTTP GET requests (e.g., `http://example.com/.env`).
**Learning:** When frontend static files are mixed in the same root directory as backend Node.js code, using `express.static` on the root exposes the entire server architecture. A security middleware must explicitly deny access to hidden files, JSON files, and backend folders before handing off the request to the static file server.
**Prevention:** Never serve the root application directory statically. Ideally, move all public-facing static files (HTML, CSS, images) into a dedicated `public/` directory and configure `express.static` to only serve from there. If restructuring is not immediately possible, always implement rigorous path-filtering middleware before the static asset handler to block access to internal paths and dotfiles.
