## 2026-05-07 - Fix Path Traversal in Image Deletion
**Vulnerability:** The `deleteImage` function in `server/controllers/upload.controller.js` allowed users to specify the `imageUrl` they wanted to delete. The input was insufficiently validated and directly passed to `fs.unlinkSync()` after path concatenation. This meant users could submit `imageUrl`s like `/uploads/../../server.js` or `../../../../etc/passwd` to delete arbitrary files on the system (Path Traversal).
**Learning:** Even when path manipulation looks secure (e.g. `imageUrl.replace('/uploads/', '')`), using `path.join` on untrusted input without further resolution validation leads to directory traversal. The application architecture did not enforce boundary checks when handling external file deletions. Additionally, the boundary check must include a trailing separator (`path.sep`) when using `startsWith`, otherwise a sibling directory with the same prefix could be accessed.
**Prevention:** Always validate resolved paths. Using `path.resolve` along with checking if the resolved path `startsWith` the base directory plus `path.sep` (`path.join(path.resolve(UPLOAD_DIR), path.sep)`) ensures the final resolved path does not fall outside the intended boundaries and protects against sibling directory traversal.
